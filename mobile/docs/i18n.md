# Internationalization (i18n)

How the mobile app keeps user-facing copy in locale catalogs instead of
hardcoding strings in components. English is the only shipped language today;
adding another should mean adding a `locales/<code>/` tree and registering it
in [`i18n/config.ts`](../i18n/config.ts).

Stack: **i18next** + **react-i18next** + **expo-localization** (device language).

---

## Layout

| Piece           | Path                                                               |
| --------------- | ------------------------------------------------------------------ |
| Locale catalogs | `locales/<locale>/` (`common.json`, feature namespaces, `errors/`) |
| Locale assembly | `locales/<locale>/messages.ts`, `errors/catalog.ts` (named files)  |
| Bootstrap       | `i18n/` (`config`, `resources`, `instance`)                        |
| React provider  | `providers/i18n-provider.tsx` (wired in `app/_layout.tsx`)         |
| Typed keys      | `i18n/types.ts` (augments `i18next` from the English catalogs)     |

Namespaces today:

- `common` — shared shell (actions, auth screens, nav titles, transport fallbacks)
- `errors` — API `code` → product copy (see [Exception handling](./exception-handling.md))

Feature namespaces (`events`, `profile`, `onboarding`, …) land as those screens
migrate. Until then, stack titles for those routes live under `common.screens`.

---

## Usage

In components and screens:

```ts
import { useTranslation } from "react-i18next";

const { t } = useTranslation("common");
t("auth.login.title");
```

Outside React (Axios interceptor, auth helpers), import the singleton from its
named file:

```ts
import i18n from "@/i18n/instance";

i18n.t("common:error.network");
```

Import config or resources from their own paths (`@/i18n/config`,
`@/i18n/resources`) when needed — do not re-export them through `instance.ts`.

Prefer `getErrorMessage` / `messageForApiErrorCode` for API failures — do not
re-translate Nest `message` bodies.

---

## Tests

Screens and components that call `useTranslation` need the app instance via
`I18nProvider` (already on the root layout). Prefer
[`testing/render.tsx`](../testing/render.tsx) (`renderWithI18n`) over bare
`render` for those trees. Shared UI defaults (`Spinner`, `Button` loading label,
bottom-sheet a11y) read the singleton with `i18n.t` so unit tests stay
provider-free — same pattern as the Axios error helpers.

For `renderHook` trees that use `useTranslation`, pass
`wrapper: I18nProvider` from `@/providers/i18n-provider`.

---

## Adding a locale later

1. Copy `locales/en/` → `locales/<code>/` and translate the JSON.
2. Add `<code>` to `locales` in `i18n/config.ts`.
3. Register the resources in `i18n/resources.ts`.
4. Keep English as `fallbackLng`. RTL (`ar` / `fa`) is out of scope until a
   language that needs it ships; prefer `start`/`end` styles in new UI.
